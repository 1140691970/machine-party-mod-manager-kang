# 技術設計草案

首版以 Windows Steam 版為目標。桌面框架、語言及部署網域待選型。以下描述實作契約，尚待原型和實機驗證。

## 遊戲定位與辨識

由 Steam 安裝位置讀取遊戲庫清單，在各庫查找 App ID 4108000 的安裝清單，使用其安裝路徑尋找遊戲執行檔及 PCK。允許從已知的版本子目錄定位檔案。記錄 Steam build、實際路徑及資料檔雜湊；相容性以經實測的組合為準。玩家搬移遊戲後重新檢查，備份按副本和安裝前的檔案指紋保存。

## 目錄、搜尋與下載

維護者發布固定的模組 ID、收錄序號、作者、README 摘要、別名與首頁。每個可安裝版本另存上游標籤或提交、資產名稱、SHA-256、支援的遊戲指紋、安裝方式、所需載入器版本、已知衝突及下載路徑。App 快取最近一次成功讀取的目錄。

可從自有網域取得目錄。發行檔逐版本選擇作者直連或 Cloudflare Worker 中轉。Worker 只解析已發布的模組 ID 和版本，向登記的上游取檔；快取與轉發依個別檔案授權決定。用戶端下載後再核對已驗證的雜湊。正式發布前，用目標地區網路實測目錄與大檔下載，記錄中斷與重試結果。

## 安裝、切換與恢復

1. 鎖定目標遊戲副本，檢查遊戲進程、遊戲版本、磁碟空間、相依項目及現有模組。辨識手動安裝、乾淨副本與未知修改；來源未明的備份不可直接當作原版。
2. 在暫存區備妥並核對所有需要的套件。依本機程式已支援的安裝方式處理，目錄資料只選擇其 ID 與固定參數。
3. 寫入安裝紀錄，保存修改前指紋、備份和必要的離線卸載工具。切換互斥模組時先驗證還原結果再套用新模組。
4. 執行上游 CLI、已驗證的腳本、或把模組加入載入器目錄。保存退出狀態，讀回目標檔案驗證，成功後記錄模組版本、安裝後指紋、擁有的檔案和依賴。
5. 程式中斷後，依紀錄及磁碟實況辨識原版、已安裝或待修復。可安全恢復時使用同一副本的備份。若 Steam 更新或玩家另有修改，停止覆寫並說明下一步。

卸載前再次檢查指紋。直接改包的模組驗證還原後 PCK；載入器型模組只移除其擁有的檔案。保留玩家先前安裝、或仍被其他模組使用的載入器。卸載成功後才清理該次交易的備份。

## 是否維護 fork

先用作者公開的 CLI 或底層安裝腳本。App 可自行承擔偵測、備份及校驗。若遇到無法從外部解決的互動或還原問題，記錄可重現案例，優先向上游提交小改動。授權允許且確有必要時才維護安裝器 fork，保留原作者、來源及版本對照。
