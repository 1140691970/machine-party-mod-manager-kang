# ADR-005：模组安装交易与备份

[English](../../en/architecture/ADR-005-install-transactions.md) · **简体中文** · [繁體中文](../../zh-TW/architecture/ADR-005-install-transactions.md)

日期：2026-11-18。状态：提议；待 Windows 上的 Overtime 验收（P2）后定稿。

## 问题

模组要么直接修改游戏 PCK，要么为 MPML 等加载器添加文件。写入失败或中断、Steam 更新、未知的手动修改，都绝不能让玩家失去可用的原版游戏。

## 提议的决策

1. 锁定目标游戏副本。把保存的 Steam 游戏根目录（用作 `installations.json` 的键）解析到实际包含 `Machine Party.pck` 的目录（如 `Machine Party_Windows`），检查游戏进程、游戏版本、磁盘空间、依赖及现有模组。区分手动安装、干净副本与未知修改；磁盘上检测到的未托管安装，只有在其还原记录的基线 SHA-256 与已知原版 PCK 指纹一致时才可接管或卸载，来源不明的备份不能直接当作原版。
2. 在 Rust 端从 Worker 端点下载所需安装包到暂存区，核对外层压缩包的字节数与 SHA-256，原样解压后再核对内部清单（`SHA256SUMS.txt` 及/或 preflight 检查）。只允许 App 已实现的安装方式（[ADR-007](ADR-007-mod-adapters.md)）；目录数据只选择 ID 与固定声明式参数。
3. 在安装记录中计算并保存修改前的基线 SHA-256 与文件大小，采用分级备份：支持差量还原的模组（如 `overtime_restore.dat`）在 App 按副本存储中镜像一份还原记录与离线卸载工具（`overtime_install.exe`）；没有自身已验证还原数据的补丁器则由 App 保存整包 PCK 备份。切换互斥模组时，先验证还原结果再应用新模组。
4. 通过内置适配器运行上游 CLI、已验证的脚本，或把模组放入加载器目录（[ADR-007](ADR-007-mod-adapters.md)）。保存退出状态，读回目标文件并确认没有未声明文件被改动，之后才记录模组版本、安装后指纹、所拥有的文件和依赖。
5. 程序中断后，根据记录与磁盘实况判断是原版、已安装还是待修复。可以安全恢复时使用同一副本的备份。若 Steam 已更新游戏或玩家另有修改，停止覆盖并说明下一步。

下载中断时，不完整的文件留在暂存区或被清除。只有确认是同一资产且服务器支持范围请求时才续传，否则重新下载；所有依赖校验完成前不动旧版本。更新写入失败时读回磁盘状态，显示实际生效的版本或修复入口。

卸载前再次检查指纹。直接改包的模组验证还原后的 PCK；加载器型模组只移除自己拥有的文件。保留玩家之前安装、或仍被其他模组使用的加载器。卸载成功后才清理该次交易的备份。

## 替代方案

依赖 Steam “验证完整性”还原文件很简单，但需要联网、会丢掉其他模组，也无法证明当前处于哪种状态。为每个安装器维护 fork 能完全掌控，但维护与授权工作成倍增加。

## 兼容性

`installations.json` 保持现有键以便读取。交易记录将以追加字段方式扩展，并且必须能继续读取现有文件。

## 所需证据

在 Steam 游戏 v2.1.2 上干净安装 Overtime v1.7，从 Steam 启动，离线卸载后原版 PCK 的 SHA-256 一致；另外模拟下载失败、写入中断与 Steam 更新，详见[产品需求](../requirements.md)。
