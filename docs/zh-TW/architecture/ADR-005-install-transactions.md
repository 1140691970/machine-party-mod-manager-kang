# ADR-005：模組安裝交易與備份

[English](../../en/architecture/ADR-005-install-transactions.md) · [简体中文](../../zh-CN/architecture/ADR-005-install-transactions.md) · **繁體中文**

日期：2026-11-18。狀態：提議；待 Windows 上的 Overtime 驗收（P2）後定稿。

## 問題

模組不是直接修改遊戲 PCK，就是為 MPML 等載入器加入檔案。寫入失敗或中斷、Steam 更新、未知的手動修改，都絕不能讓玩家失去可用的原版遊戲。

## 提議的決策

1. 鎖定目標遊戲副本。將已保存的 Steam 遊戲根目錄（作為 `installations.json` 的鍵）解析到實際包含 `Machine Party.pck` 的目錄（如 `Machine Party_Windows`），檢查遊戲進程、遊戲版本、磁碟空間、相依項目及現有模組。辨識手動安裝、乾淨副本與未知修改；磁碟上偵測到的未託管安裝，只有在其還原紀錄的基線 SHA-256 與已知原版 PCK 指紋一致時才可接管或卸載，來源未明的備份不可直接當作原版。
2. 在 Rust 端從 Worker 端點下載所需套件到暫存區，核對外層壓縮包的位元組數與 SHA-256，原樣解壓後再核對內部清單（`SHA256SUMS.txt` 及／或 preflight 檢查）。只允許本機程式已實作的安裝方式（[ADR-007](ADR-007-mod-adapters.md)）；目錄資料只選擇 ID 與固定宣告式參數。
3. 在安裝紀錄中計算並保存修改前的基線 SHA-256 與檔案大小，採用分級備份：支援差量還原的模組（如 `overtime_restore.dat`）在 App 按副本儲存中鏡像一份還原紀錄與離線卸載工具（`overtime_install.exe`）；沒有自身已驗證還原資料的補丁器則由 App 保存整包 PCK 備份。切換互斥模組時先驗證還原結果再套用新模組。
4. 透過內建適配器執行上游 CLI、已驗證的腳本、或把模組加入載入器目錄（[ADR-007](ADR-007-mod-adapters.md)）。保存退出狀態，讀回目標檔案並確認沒有未宣告檔案被改動，成功後才記錄模組版本、安裝後指紋、擁有的檔案和依賴。
5. 程式中斷後，依紀錄及磁碟實況辨識原版、已安裝或待修復。可安全恢復時使用同一副本的備份。若 Steam 更新或玩家另有修改，停止覆寫並說明下一步。

下載中斷時將不完整檔案留在暫存區或清除。重試時只有在可確認同一資產且伺服器支援範圍請求時續傳，否則重新下載；全部依賴校驗完成才動到舊版本。更新寫入失敗時讀回磁碟狀態，顯示實際生效版本或修復入口。

卸載前再次檢查指紋。直接改包的模組驗證還原後 PCK；載入器型模組只移除其擁有的檔案。保留玩家先前安裝、或仍被其他模組使用的載入器。卸載成功後才清理該次交易的備份。

## 替代方案

依賴 Steam「驗證完整性」還原檔案很簡單，但需要連網、會丟掉其他模組，也無法證明目前處於哪種狀態。為每個安裝器維護 fork 能完全掌控，但維護與授權工作成倍增加。

## 相容性

`installations.json` 維持現有鍵以便讀取。交易紀錄將以追加欄位方式擴充，且必須能繼續讀取現有檔案。

## 所需證據

在 Steam 遊戲 v2.1.2 上乾淨安裝 Overtime v1.7，從 Steam 啟動，離線卸載後原版 PCK 的 SHA-256 一致；另模擬下載失敗、寫入中斷與 Steam 更新，詳見[產品需求](../requirements.md)。
